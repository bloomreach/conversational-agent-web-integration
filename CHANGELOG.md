# Changelog

What changed in the documented contract (configuration, runtime API, hooks and events, styles) with each widget
release published here. The version headings are the widget release tags.

## v2.42.20 — 2026-11-13

- [Search orchestration version 2](guides/07-search-orchestration.md): the Helper Tag version 2 classifies search queries with Bloomreach's classifier service instead of on the page, and adds `window.CLARITY_HELPER.onFocus()`; [Moving from version 1 to version 2](guides/07-search-orchestration.md#moving-from-version-1-to-version-2) lists the changes to your search handler. It uses [`@bloomreach/clarity-utils`](reference/clarity-utils.md) 1.0.21 (npm tag `next`). **Breaking** in 1.0.21: `isSearch()` returns a `Promise<boolean>` instead of a `boolean`, so `await` it, since a `Promise` is always truthy. Also new in 1.0.21: the `api` mode (`classifierUrl`, `agentId`, `classifierTimeoutMs`), `warmUp()`, `setup()` `timeoutMs`, and `mode: 'list'` applying the word lists (in 1.0.20 it classifies like `score`). `window.CLARITY_HELPER.isSearch` already returned a `Promise`. The Helper Tag of both versions now also resolves `true` for an empty query and when the chat cannot be opened (no orchestrator weblayer for the page's locale, or no Conversational Agent weblayer started yet, with `fallback: 'chat_unavailable'` on the `search_orchestrator` event), so the only check a search handler needs is that `window.CLARITY_HELPER` exists; ask your Bloomreach contact to update your Helper Tag, as for the switch to version 2.
- **Breaking:** the PayPal checkout's `purchase` hook and analytics event now fire only for an approved payment, and no longer carry `purchase_status` or `error`. A failed checkout fires the new [`checkoutError`](reference/hooks.md#purchase-checkoutcancel-checkouterror) hook (action `checkout_error`, with `error`), and a checkout that ends without a payment or an error fires the new `checkoutCancel` hook (action `checkout_cancel`, with `message`: `'paypal_closed'`, `'chat_closed'` or `'new_checkout'`). Reports filtering `purchase` on `purchase_status` should use the three actions instead.
- Corrections after a review of these pages against the widget code: `PARAM_showAfter` is in seconds; the trigger hook for the first paint is `actualShow` (`version: '2'`); `open_chat` neither pre-fills nor sends its `input`; a quick reply sends its label to Zendesk; only the Search Suggestion trigger answers `window.CLARITY_WEBLAYER.call`; the side panel's DOM order, the weblayer safety gates and their fields, and a number of class names are described as the code implements them; `delete_chat` takes no arguments; with `initialState: 0` the chat expands once the first message of a new chat has loaded, whether or not an `initialMessage` is set (not when `suppressInitialMessage` is set or the home screen shows); `initialState: 2` opens the chat on every page load, also after the shopper minimized it, except on the full-screen mobile widget, which also restores no open state on later page loads.
- The [function hooks](reference/hooks.md#function-hooks) set in a weblayer's `widget.hooks` are now called, and hooks a page sets on `window.CLARITY_CONFIG.hooks` are no longer dropped when a weblayer loads the widget; see [Hooks on a weblayer page](reference/hooks.md#hooks-on-a-weblayer-page). Standalone configurations can set function hooks per source in [`bannerSettings`](reference/widget-config.md#bannersettings).
- [`window.CLARITY.call`](reference/runtime-api.md#callaction-args-source): a `source` argument or `setSource` call made before the bundle loads is no longer lost (update the inline snippet to keep them); `user_send_message` and `sync_chat` resolve to the same shapes in mobile AI Mode as in the default widget; a [Helper Tag](guides/07-search-orchestration.md) search started before the bundle loads now runs on the orchestrator weblayer.
- Fixes: the weblayer's seven style shorthands (`PARAM_zIndex`, `PARAM_widgetFont`, …) override `widget.ui` only when set; `group` is matched case-insensitively; `PARAM_initialState` accepts a numeric string; a `vh` value of `PARAM_maxChatContainerHeight` other than the default applies; `initialMessage.itemIdsToShow`, `placeholderStrings` and `showPlaceholderStringsHome` apply without a `text`; `desktopTemplate` is also read from `ui.desktop`; a custom carousel's `onAddToCart(variantId)` adds that variant; a `priceAttributesToUse` list is re-sent when an entry or its `primary` flag changes, also when its length stays the same (a [reordered list](guides/06-context-aware-pricing.md#known-issues) is still not); analytics events reach `clarity_session_state: 'clarity_interacted'` and count every interaction in `clarity_session_interaction_count`; the chat's and the mini PDP's scroll containers carry [`clarity-touch-enclosed-container`](reference/styles.md).
- Documented: [`ui.enableSendingMessageWhileStreaming`](reference/widget-config.md#feature-flags), [`getContext().userContextFilter`](reference/widget-config.md#getcontext-contextfields), the trigger's [`onPromptClicked`](reference/weblayer-config.md#prompt-click-pdp-embedded--plp-embedded--plp-banner--search-suggestion), and the classes `clarity-mount-wrapper`, `clarity-mini-pdp-wrapper`, `clarity-mobile-pdp-backdrop`, `clarity-live-chat-container` and `clarity-button` in [`styles.md`](reference/styles.md).
- Zendesk hand-over: with the Support API OAuth client configured, the shopper's *End live support conversation* now solves the ticket (with one conversation per customer once a human agent has replied in that live session, with one conversation per live phase on every ending), so the [*Solved → End session* trigger](guides/08-customer-service-zendesk.md#34-control-must-return-to-your-ai-agent-when-the-human-agent-is-done) ends the agent's messaging session and the shopper's next hand-off starts a new ticket at the AI agent. The client needs `tickets:read` and `tickets:write` in its allowed scopes, next to `users:read` and `users:write` ([3.3](guides/08-customer-service-zendesk.md#33-support-api-oauth-client--optional)).
- Zendesk hand-over: a satisfaction survey app's message sent after the live session ended, such as Simplesat's once the ticket is solved, now reaches the shopper when the app is named to Bloomreach as the new optional [satisfaction survey app](guides/08-customer-service-zendesk.md#4-what-to-hand-to-bloomreach); the chat stays back with Clarity.
- New guides: [Style the widget](guides/02-style-the-widget.md), with annotated screenshots of the main classes and how to write overrides that win, and [Track events](guides/04-track-events.md), which browser event and Engagement action to use for what. [`styles.md`](reference/styles.md) now opens with the rule that an override needs a selector in front of the class, and no longer lists `clarity-keyboard-filler`, which is not meant to be restyled. The [README](README.md#versions) says how a documented version matches the widget your page runs, and [`open_chat`](reference/runtime-api.md#open_chat) what it does while the widget is hidden.
- The [guides](guides/README.md) are renumbered so the tasks most integrations need come first: triggers, styling, custom components, event tracking, then the optional features. Links to the old file names, such as `guides/02-customize-components.md`, no longer resolve.

## v2.42.10 — 2026-11-10

- **Breaking:** `ui.hideSearchResultCarousels` is replaced by the function [`ui.fn.hideSearchResultCarousels`](guides/02-customize-components.md#fnhidesearchresultcarousels), asked once per search result batch, so a page can keep search results in the chat where it has no results grid, such as a product detail page. Unset, it keeps the old default: results go to the page under `desktopTemplate: 'ai_mode'` and stay in the chat otherwise. Replace `hideSearchResultCarousels: true` / `false` with `fn: { hideSearchResultCarousels: () => true }` / `() => false`.
- Zendesk hand-over: the first message of each new conversation is held back for 2 seconds by default, so the merchant's AI agent has taken the conversation over and answers it instead of replying with its welcome alone. The welcome reply now shows above the shopper's hand-off message. The wait is a new optional value to hand to Bloomreach, the [AI agent takeover wait](guides/06-customer-service-zendesk.md#4-what-to-hand-to-bloomreach).
- Sierra satisfaction survey: a rated survey stays in the chat with its stars; an unrated one is disabled after five minutes under an overlay showing the new [`ui.sierraRatingTimeoutLabel`](reference/widget-config.md#uisierraratingtimeoutlabel) (styles: `clarity-agent-csat-survey-expired`, `clarity-agent-csat-survey-overlay`, `clarity-agent-csat-survey-overlay-label`).
- New `checkout` and `purchase` hooks and analytics events for the PayPal checkout of the mini PDP's Buy now button, with `product_ids`, `checkout_location`, `checkout_provider`, `purchase_status`, `order_id` and `error`. The top notice (`clarity-feedback-thank`) moved from the chat pane to the chat container so it also shows over the inline mini PDP, and gained a `clarity-feedback-thank--error` variant used for a failed checkout; new `checkoutSuccessful` / `checkoutFailed` texts. A failed checkout closes the overlay and reports through that notice instead of an in-overlay error message, so `clarity-paypal-error` is gone. `clarity-paypal-widget` no longer paints a white background; it blurs the chat behind it (`backdrop-filter: blur(3px)`), and it now stays mounted while the chat is open, hidden with the new `clarity-paypal-widget-idle` modifier between checkouts.
- Mini PDP in the `mobileMiniPDPOverlay` panel: top padding reduced from 80px to 40px, since only the drag handle sits above it there (the inline mini PDP under the chat header keeps 80px).
- `userRespondProduct` hook and `user_respond_product` analytics event: the per-product rows no longer carry `product_names` (the parent `userRespond` never did); use `product_id`.
- First publication of the web integration documentation: configuration references for the widget and the
  weblayer, the runtime API, hooks and analytics events, styles, the `@bloomreach/clarity-utils` classifier, and
  guides for triggers, component customization, the side panel, context-aware pricing, search orchestration and
  the Zendesk hand-over.
